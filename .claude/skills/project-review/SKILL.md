# 변경 검토

변경한 코드와 문서를 검토하고, 확신도 점수로 잘못된 지적을 걸러 냅니다. 내장 `/code-review`와 이름이 겹치지 않게 `project-review`로 둡니다.

## 검토 범위

기본은 `git diff`의 스테이징하지 않은 변경입니다. git 저장소가 아니거나 사용자가 파일을 지정하면 그 파일을 봅니다.

## 검토 기준

### 프로젝트 규칙 (AGENT.md "작업 규칙")
- 자격 증명이 코드, 매니페스트, Terraform state 밖의 파일, 문서, 결과 파일에 들어가지 않았는지. AWS 권한은 EKS Pod Identity와 IAM 역할로만 부여했는지
- CRD 필드, Helm values, vLLM 플래그를 실제 설치 버전에서 확인했는지. 확인하지 못한 값에 `TODO(verify)`가 있는지
- 문서의 수치가 `results/`의 원시 자료로 뒷받침되는지. 측정하지 않은 값을 측정한 것처럼 쓰지 않았는지
- 서빙 파드가 Hugging Face에서 직접 내려받지 않고 S3에서만 읽는지
- 요청 범위 밖의 기능, 불필요한 추상화, 중복 코드가 없는지. 주석이 이유와 제약만 적는지
- README와 docs의 한국어가 합니다체인지

### 파일 사이의 일관성
- BFF의 경로, 요청 헤더, 응답 헤더를 바꿨으면 `docs/07-bff.md`, `docs/api-reference.md`, 화면의 소비 코드(`app/web/src`)가 함께 바뀌었는지
- 화면 문구가 `tr(한국어, 영어)` 쌍인지, BFF 문구가 `app/bff/texts.py`에 두 언어로 있는지
- 매니페스트를 바꿨으면 AGENT.md의 "확정된 결정"과 해당 단계 문서가 맞는지
- 계정 ID, ARN, CloudFront 주소 같은 환경 식별 값이 추적하는 파일에 들어가지 않았는지(`python3 scripts/mask-identifiers.py --check <경로>`). 환경별 값이 든 파일을 고쳤으면 `*.example`도 함께 고쳤는지. 화면을 찍은 그림에 로그인한 계정이 보이지 않는지

### 버그
- 논리 오류, 빈 값 처리, 경쟁 조건
- 스트리밍을 모아서 내보내는 코드(SSE가 깨집니다), 타임아웃과 재시도
- 인증 없이 열리는 경로, 민감 정보 요청이 Gemma 밖으로 나가는 경로

### 품질
- 중복, 과한 복잡도, 빠진 시험

## 확신도 점수

문제마다 0에서 100으로 점수를 매깁니다.

| 점수 | 뜻 |
|---|---|
| 0 | 잘못된 지적이거나 이번 변경 이전부터 있던 문제 |
| 25 | 실제 문제일 수 있으나 확인하지 못함 |
| 50 | 실제 문제이나 사소함 |
| 75 | 확인한 실제 문제이고 동작에 영향이 있음 |
| 100 | 확실하고 자주 일어남 |

**75 이상만 보고합니다.**

## 출력 형식

문제마다 다음을 적습니다.

```
### [CRITICAL|IMPORTANT] <제목> (확신도: XX)
**파일:** `path/to/file.ext:line`
**문제:** <무엇이 왜 문제인지>
**근거:** <AGENT.md의 규칙 또는 확인한 사실>
**고칠 방법:** <구체적인 수정>
```

75 이상인 문제가 없으면 무엇을 확인했는지 짧게 적고 끝냅니다.
