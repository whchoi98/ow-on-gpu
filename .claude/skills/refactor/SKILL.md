# 리팩터링

동작은 그대로 두고 구조만 고칩니다.

## 원칙
- 동작을 바꾸지 않습니다. 동작을 바꿔야 하면 리팩터링과 따로 다룹니다
- 작은 단계로 나누고 단계마다 시험을 돌립니다
- 요청받은 범위만 고칩니다. 범위 밖의 정리는 제안으로 남깁니다(AGENT.md 작업 규칙)
- 추상화는 같은 코드가 실제로 반복될 때만 넣습니다

## 절차

### 1. 지금 상태 확인
- 고칠 코드와 그 코드를 부르는 곳을 읽습니다
- 시험이 그 코드를 다루는지 확인합니다. 다루지 않으면 먼저 지금 동작을 고정하는 시험을 넣습니다

### 2. 시험이 통과하는지 확인
```bash
# BFF (이미지 안에서 실행. 장비의 Python으로는 고정한 의존성을 설치할 수 없습니다)
docker run --rm -v "$PWD/app/bff":/app:ro -w /app <BFF 이미지> python -m unittest test_bff

# 화면
npm test --prefix app/web

# 하네스
bash tests/run-all.sh
```

### 3. 한 단계씩 고치기
- 한 번에 한 가지만 바꿉니다(이름, 추출, 이동 가운데 하나)
- 바꿀 때마다 위 시험을 다시 돌립니다

### 4. 마무리
- 측정에 쓰는 경로(BFF의 요청 처리, 측정 스크립트)를 고쳤으면 기존 측정값의 조건이 달라지지 않았는지 적습니다
- 인포그래픽 소스를 고쳤으면 `docs/infographic/build.sh`로 그림이 같은지 확인합니다

## 하지 않는 것
- 배포. 리팩터링한 코드를 배포하려면 `/deploy`의 승인 절차를 따릅니다
- 측정값이 바뀌는 변경. 조건이 달라지면 다시 측정해야 합니다
